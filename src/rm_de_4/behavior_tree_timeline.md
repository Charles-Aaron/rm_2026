# RoboMaster 哨兵机器人行为树时间流程图

## 整体执行时序 (50Hz循环)

```
时间轴: 0ms ────────────────────────────────────────────────────────── 20ms ── 50Hz循环
        │
        ├─ 1. 检查比赛状态 (GameStatusSub)
        │   └─ 等待 start_status = 4 (比赛开始信号)
        │
        └─ 2. 主决策逻辑 (Fallback - 按优先级执行)
```

## 详细优先级执行流程

### 优先级1: 攻击前哨站 (attack_outpost)
```
条件检查 ──→ 状态检查 ──→ 导航执行
   │           │           │
   │           │           └─ 目标: (10, 2, 0)
   │           └─ 血量≥150 & 弹量≥50
   └─ 敌方前哨站HP > 0
```

### 优先级2: 智能补给 (smart_supply)
```
选择补给点 ──→ 导航到补给点
     │              │
     └─ 计算最佳位置    └─ 动态目标位置
```

### 优先级3: 终局策略 (endgame_strategy)
```
终局补给检查 ──→ 补给执行 ──→ 恢复检查 ──→ 攻击/防守决策
      │              │           │           │
      │              └─ 目标: (1, 3, 0)      └─ 防守基地: (-5, 1, 0)
      └─ 基于剩余时间判断
```

### 优先级4: 冲击敌方增益 (rush_enemy_buff)
```
计算冲击策略 ──→ 导航到敌方增益点
      │              │
      └─ 敌方增益位置    └─ 动态目标位置
```

### 优先级5: 日常巡逻 (patrol)
```
状态检查 ──→ 选择巡逻点 ──→ 导航巡逻
   │           │           │
   │           └─ 随机选择    └─ 巡逻位置:
   └─ 血量≥150 & 弹量≥50        (2,2,0) / (3,1,0) / (1,3,0)
```

### 优先级6: 堡垒增益守卫 (fortress_buff)
```
队友阵亡检查 ──→ 前往增益点 ──→ 守卫执行
      │              │           │
      │              └─ 目标: (1, -0.5, 0)  └─ 持续60秒
      └─ 1/3/4号机器人HP = 0
```

### 优先级7: 保底回基地 (go_home)
```
直接执行 ──→ 返回基地
    │           │
    └─ 无前置条件    └─ 目标: (-1, 2, 0)
```

### 优先级8: 初始移动 (initial_move)
```
最后执行 ──→ 初始位置
    │           │
    └─ 所有分支失败    └─ 目标: (0.5, 1, 0)
```

## 节点执行时间分析

### 条件节点执行时间 (毫秒级)
```
GameStatusSub:     ~1ms  (状态检查)
RobotStatusSub:    ~2ms  (血量/弹量检查)
OutpostAttack:     ~1ms  (前哨站状态)
AlliesDown:        ~1ms  (队友状态)
EndgameNeedSupply: ~1ms  (时间/状态判断)
RecoveredEnough:   ~1ms  (恢复状态检查)
```

### 动作节点执行时间
```
SendGoalAction:     ~5ms  (发送导航指令)
SelectSupplyPoint:  ~2ms  (计算补给点)
RandomPatrolPose:   ~1ms  (随机选择)
RushEnemyBuff:      ~2ms  (策略计算)
GuardFortress:      ~1ms  (守卫逻辑)
```

## 典型场景时间线

### 场景1: 正常比赛流程
```
0ms:  检查比赛状态
1ms:  检查前哨站攻击条件
2ms:  检查机器人状态 (血量150+, 弹量50+)
3ms:  发送导航指令到前哨站
8ms:  等待导航完成...
```

### 场景2: 需要补给场景
```
0ms:  检查比赛状态
1ms:  前哨站攻击条件失败
2ms:  选择补给点
4ms:  发送导航指令到补给点
9ms:  等待导航完成...
```

### 场景3: 队友阵亡场景
```
0ms:  检查比赛状态
1ms:  前哨站攻击条件失败
2ms:  补给条件失败
3ms:  终局策略失败
4ms:  冲击增益失败
5ms:  巡逻条件失败
6ms:  检测到队友阵亡
7ms:  前往堡垒增益点
12ms: 开始守卫60秒
```

## 关键时间节点

### 比赛阶段识别
```
准备阶段: start_status = 1
比赛开始: start_status = 4  ← 行为树开始执行
比赛结束: start_status = 3
```

### 补给时机判断
```
血量 < 150: 立即补给
弹量 < 50:  立即补给
剩余时间 < 60秒: 终局补给策略
```

### 策略切换时机
```
前哨站HP = 0: 切换到基地攻击
队友全部阵亡: 切换到防守模式
比赛剩余时间 < 30秒: 切换到终局策略
```

## 性能优化点

1. **条件检查优化**: 使用原子变量避免锁竞争
2. **导航指令缓存**: 避免重复发送相同目标
3. **状态订阅优化**: 使用回调机制减少轮询
4. **决策频率**: 50Hz确保响应及时性

## 异常处理时间

```
导航失败:    立即重试 (5ms内)
通信中断:    使用缓存数据继续执行
状态异常:    降级到保底策略
系统错误:    执行初始移动作为安全措施
```
